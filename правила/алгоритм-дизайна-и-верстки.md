# Обязательный алгоритм дизайна и верстки страниц АБС

Это правило применяется при создании и редактировании каждой страницы сайта АБС.

## Источники

1. **Типографика** — проектные шаблоны. На сайте используется только семейство шрифтов `Open Sans`.
2. **Основной визуальный дизайн и UX** — папка `Template libraries/Визуальный стиль сайта`.
3. **Главные визуальные шаблоны** — `Example 1.jpg`, `Example 2.jpg`, `Example 3.jpg`.
4. **Дополнительные визуальные ориентиры** — остальные изображения из папки `Template libraries/Визуальный стиль сайта`. Использовать их можно, если основным шаблонам недостаточно контекста для конкретного блока.
5. **Фирменные цвета** — только палитра и правила применения из `Template libraries/Визуальный стиль сайта/guide-page1.png`.
6. **Сетка** — только Bootstrap 5 и схема из `Template libraries/bootstrap-5-grid-12-columns.html`.
7. **Компоненты и иконки** — проектные библиотеки из `Template libraries`.
8. **Структура страниц и SEO-семантика** — материалы из `The structure and semantics of the website`.

## Единая иерархия заголовков

- H1, H2 и H3 используют только глобальную типографическую шкалу: H1 — `clamp(2rem, 3vw, 2.1875rem)` вне hero-блока; H2 — `clamp(2rem, 3vw, 2.625rem)` с межстрочным интервалом `1.18`; H3 — `1.5rem` с межстрочным интервалом `1.25`.
- Все H2 на странице используют единый размер, межстрочный интервал и начертание из глобальной типографики. Нельзя локально увеличивать или уменьшать отдельный H2 для декоративного эффекта.
- Все H3 на странице используют единый размер, межстрочный интервал и начертание из глобальной типографики. Если тексту нужна роль подписи или маркера, использовать `p` или `span` с семантическим классом, а не менять размер H3. Исключение — названия в карточках навигации: это компонентные подписи, для которых сохраняется компактный размер.

## Порядок работы над страницей

1. Изучить структуру, семантику и подготовленный текст страницы.
2. Определить состав и последовательность блоков без изменения утвержденного смысла.
3. Подобрать композицию и UX по основным шаблонам `Example 1–3`.
4. При необходимости свериться с дополнительными изображениями из папки визуального стиля.
5. Применить только фирменные цвета из `guide-page1.png`.
6. Использовать `Open Sans` для всей типографики.
7. Сверстать страницу исключительно на Bootstrap 5:
   - Bootstrap Grid;
   - Bootstrap Utilities;
   - Bootstrap Components;
   - 12-колоночная сетка;
   - адаптация под мобильные, планшетные и настольные устройства.
8. Дополнительный CSS использовать только поверх Bootstrap для фирменного оформления. Не создавать собственную grid-систему и не менять структуру Bootstrap.
9. Проверить страницу на всех основных ширинах экрана, визуальную иерархию, читаемость, единый стиль компонентов и соответствие исходным материалам.
10. Результат работы — полностью готовая адаптивная сверстанная страница.

## Тексты страниц

- Для каждой новой страницы до начала вёрстки создавать один отдельный рабочий файл Word `.docx` с полным текстом страницы: заголовками, основными абзацами, карточками, списками, CTA, текстом формы и FAQ.
- Все рабочие тексты страниц хранить только в `Textes`. Имя файла: `Текст страницы - <человекопонятное название страницы>.docx`.
- Этот DOCX является единственным рабочим источником текста страницы. После согласования и при любой следующей корректировке редактировать тот же файл, а не создавать его новые версии, копии или дубли.
- Сначала обновить текст в рабочем DOCX, затем перенести согласованные изменения в данные/шаблон страницы. Не переписывать утвержденный текст в коде самостоятельно.
- Перед началом вёрстки убедиться, что для страницы есть её отдельный DOCX в `Textes`; при отсутствии текста зафиксировать комментарий и не придумывать недостающий контент.

## Кнопки

- Все основные CTA-кнопки сайта используют одинаковое скругление `10px`.
- Эталон основных CTA-кнопок — кнопка в хэдере: `Open Sans`, `16px`, `700`, одинаковая высота, внутренние отступы и радиус `10px`.
- На главной странице кнопки «Подобрать персонал», «Оставить заявку на подбор» и кнопка отправки формы используют параметры кнопки хедера. Увеличенный вариант `.btn-lg` для этих CTA не применяется.
- Главная CTA-кнопка использует фирменный цвет `#E03B32`, если для конкретного блока не утверждено другое решение.
- Подзаголовки, подписи и текстовые маркеры не должны выглядеть как CTA-кнопки: не использовать для них красную плашку, кнопку-подобные отступы или интерактивную форму, если элемент не выполняет действие.

## Карточки и модули

- Самостоятельные модули-карточки используют единое скругление `16px` (`--abs-radius-lg`), как у карточек основных блоков главной страницы.
- При создании следующих страниц использовать согласованный визуальный язык готовых страниц: Open Sans, типографическую шкалу, Bootstrap-сетку, ритм отступов, пропорции, иконки, булеты, безопасные зоны текста и медиа. Новые блоки должны быть выразительными и содержательно связанными с задачей страницы, а не шаблонными или топорными; типовые компоненты можно переиспользовать, но новые текстовые и смысловые блоки нельзя механически копировать.
- Пересечение H1–H3, обычного текста, списков или CTA с изображением считается ошибкой вёрстки. При любом изменении композиции проверить безопасную область для текста на desktop и mobile; если контент может наехать на медиа, скорректировать сетку, размеры, отступы или положение изображения до завершения задачи.
- В модуле, где текст расположен над закреплённым внизу изображением, между последней строкой текста и медиа обязательно оставлять визуальную безопасную зону не менее `32px`; при длинном заголовке увеличивать высоту модуля, а не уменьшать интервал или допускать прилипание текста к картинке.
- Для коротких списков в плитках использовать Bootstrap `row` / `col` с равными ячейками: на desktop — сетка `2 × 2`, на мобильных — одна колонка. Для равных горизонтальных и вертикальных интервалов применять один класс Bootstrap `g-4` (`24px`), а не смешивать `gx-*` и `gy-*`. Фон, скругление и внутренний отступ задавать вложенной плитке внутри `col`, а не самому столбцу: так фон не перекрывает Bootstrap gutter и элементы не соприкасаются. Внутренний отступ плитки — `24px`, интервал между иконкой и текстом — `12px`, иконка помещается в квадрат `44px`, а текст списка использует интервал `1.45–1.5`. Иконка и первая строка текста выравниваются по одной вертикальной оси. Не добавлять рамку плитке, если она не требуется как функциональный сигнал: разделять модули отступом, фоном и скруглением.
- В списках проверок использовать заполненную фирменную красную иконку-галочку из проектной библиотеки и интервал `12px` между иконкой и текстом. Для равного расстояния между строками и колонками применять Bootstrap `g-4` (`24px`). Галочка выравнивается по первой строке текста, а не по центру всего многострочного пункта; вертикальная поправка иконки — `2px`.
- Списки проверок на посадочных страницах выводить одной вертикальной Bootstrap-колонкой `col-12`: так длинные требования не дробятся на узкие строки. Плитка списка использует обычное начертание `400`. Изображение внутри цветного модуля, которое должно прилегать к его нижней границе, фиксируется через `bottom: 0` без внутреннего нижнего отступа.
- Акцентную иконку в верхней части цветного модуля можно вынести в левый верхний угол абсолютным позиционированием. Внутренние отступы сверху и слева должны быть равными (`24px`), а заголовок должен сохранять отдельную безопасную линию и не зависеть от потока иконки. Для плиточного списка проверять, что Bootstrap-строки растянуты одинаково и все ячейки без внешних смещений укладываются в единый мнимый прямоугольник.
- Для одинаковой высоты элементов в Bootstrap-сетке `col` получает `d-flex`, а внутренняя плитка — `w-100 h-100`. На desktop допускается единая фиксированная высота, рассчитанная по самому длинному пункту; на мобильных высота должна оставаться автоматической. Не увеличивать внутренние отступы ради заполнения пространства: сначала использовать внешний gutter `g-4`, затем компактный равный padding плитки.
- Фотография, текст и список внутри смыслового модуля должны собираться в единую композицию. Нельзя располагать их как несвязанные окна или одиночные прямоугольники: использовать уместные графические связки из утвержденных референсов — подложки, точечные паттерны, пересечения, акцентные ярлыки и единый контур композиции.
- Декоративные элементы должны поддерживать иерархию и тему блока, а не быть случайным украшением. Не копировать приемы механически: адаптировать их под фирменную палитру, Bootstrap-сетку и содержание конкретного блока.

## Сквозные элементы

- Header и footer являются сквозными компонентами. Для любой страницы использовать единые исходники из `src/components` и общие стили из `src/assets/css/site.css`.
- Нельзя создавать дубликаты верстки или локальные версии header/footer для отдельной страницы, шаблона или выборочной группы страниц.
- Изменения header/footer вносятся только в общий компонент или его общий CSS, после чего проверяются на всех типах страниц.
- Главная страница является эталоном композиции первого экрана для всех страниц: расположение и размер hero-изображения, темная подложка, положение текстового контента, а также расположение и поведение header должны быть одинаковыми.
- При создании новой страницы заменяется только hero-изображение на уникальное по содержанию. Его контейнер, размеры, кадрирование и адаптивное поведение сохраняются по эталону главной страницы.
- Hero-стили не дублируются в шаблонах отдельных страниц: любые корректировки композиции первого экрана вносятся в общий слой `.page-template--hero-layout` и проверяются на главной и внутренних страницах.
- При генерации hero-изображения ключевой объект, в частности лицо специалиста, размещается ниже безопасной зоны плавающего header и остается полностью видимым на всех контрольных ширинах экрана.
- Для изображений первого экрана используется единая графитовая маска с едва заметным холодным смещением на основе фирменного темно-синего цвета `#3D4A61` и базового черного `#333333`; прозрачность `42%`. Маска должна быть ровной, без градиента, выглядеть как естественное затемнение фотографии, обеспечивать уверенный контраст для H1 и подзаголовка и не восприниматься как цветная пелена.
- На внутренних страницах хлебные крошки располагаются в верхней части первого экрана, под header и перед H1. Использовать общий компонент `src/components/breadcrumbs.html` и Bootstrap-колонки, совпадающие с колонкой H1; при абсолютном позиционировании компенсировать внешний отступ через стандартную половину `--bs-gutter-x`, а не ручными пиксельными значениями. Не выводить крошки отдельной полосой под hero и не размещать их внизу первого экрана.
- Каждая новая внутренняя SEO-страница должна содержать хлебные крошки. Использовать только общий компонент `src/components/breadcrumbs.html`, подключаемый сборщиком; не создавать отдельную разметку или CSS-версию крошек для конкретной страницы.
- На страницах без первого экрана с изображением крошки размещаются над основным контентом внутри Bootstrap-контейнера. Общие стили крошек хранятся только в `src/assets/css/site.css`.

## Изображения

- Для первого экрана каждой новой страницы создавать новое уникальное изображение, соответствующее ее услуге и поисковому интенту.
- Изображения внутри одной страницы и между разными страницами не должны дублироваться без отдельного согласованного решения.
- Не использовать одно и то же изображение повторно в разных блоках как декоративную заглушку.

## Цвет текста

- Если в макете нужен чёрный текст, использовать только `#333333`. Не применять произвольные оттенки чёрного.
- На темном фоне не использовать мелкие красные элементы как единственный носитель смысла: для нумерации, булетов и других небольших маркеров применять светлые контрастные элементы в гамме главной страницы. Красный оставлять для крупных CTA и фирменных акцентов с достаточной площадью.

## Приоритет при противоречиях

- При каждой работе с дизайном и вёрсткой обязательно применять проектные правила дизайна, UX/UI, типографики, Bootstrap-сетки и активный навык `frontend-design`; личные предпочтения и типовые решения им не противоречат.
- Публикация страниц и menu: основные пункты header и footer всегда выводятся для цельной навигационной композиции. В popup-меню header отображать только страницы со статусом `"ready"` в файле `src/data/pages/*.json`. Будущие URL и пункты семантической структуры хранить со статусом планирования, но не удалять; они не должны рендериться внутри popup header. После создания страницы и установки `"status": "ready"` сборщик автоматически добавляет её человекопонятное название в соответствующий dropdown. До готовности карточки и пункты могут быть показаны визуально, но не должны содержать ссылку на несуществующий URL; после перевода страницы в `"ready"` сборщик добавляет ссылку автоматически. Для URL без готовой страницы не создавать каталог или шаблон-заглушку в `dist`: он должен возвращать `404`.
- SEO-публикация: сборщик автоматически ставит `index, follow` на все публичные страницы, генерирует для них canonical, единый JSON-LD `@graph` (`Organization`, `WebSite`, `WebPage`, `BreadcrumbList`, а при наличии видимого FAQ — `FAQPage`) и включает их в автоматически созданный `sitemap.xml`. `BreadcrumbList` формируется для каждой публичной страницы по единым правилам, включая главную. Для каждой публичной страницы сборщик также автоматически выводит полный набор Open Graph и Twitter Card: абсолютный `og:image` уникального hero-изображения страницы, его размер, тип и alt. При создании новой публичной страницы достаточно добавить корректный canonical, уникальное hero-изображение и статус `"ready"`: в следующей сборке она появится в карте сайта, получит микроразметку и превью. Технические URL (`/404.html`, `/_prototype/`, `/request/`, `/thanks/`) всегда получают `noindex, nofollow`, закрываются в `robots.txt` и исключаются из sitemap.
