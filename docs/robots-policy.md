# Robots.txt сайта АБС

Обновлён 29 октября 2026 года. Источник: src/seo/robots.txt, копируется сборщиком в dist/robots.txt без преобразования.

## Правила

- Googlebot — отдельная секция.
- Yandex — отдельная секция с Clean-param для рекламных идентификаторов и UTM-меток.
- User-agent: * — те же границы обхода для остальных совместимых роботов.
- Allow: / оставляет открытыми рабочие разделы, новые страницы, юридические документы, CSS, JavaScript, изображения и шрифты.
- В каждой секции повторены ограничения /_prototype/, /actions/, /var/, /release-manifest.sha256 и /abs-deploy-version.txt. Конкретные секции не наследуют общую секцию автоматически.
- /request/, /thanks/ и /404.html доступны для обхода, чтобы робот мог прочитать существующий meta robots noindex. В sitemap их нет. Задача исключения из индекса не подменяется запретом обхода.
- Sitemap: https://abs-engineer.ru/sitemap.xml объявлен один раз и применяется ко всем роботам.

Google не поддерживает Clean-param; эта директива оставлена только в секции Яндекса. Указанные параметры не меняют содержимое статических страниц сайта. Функциональный параметр status формы не включён в Clean-param. Маски Disallow: /*?* и запреты обхода UTM не используются: робот должен прочитать canonical и запрет индексации.

## Исключение UTM-дублей из индекса

src/seo/.htaccess копируется в корень dist. Для любого имени параметра utm_* (без учёта регистра), в начале строки параметров или после &, Apache с mod_headers возвращает X-Robots-Tag: noindex, follow. Наличие или отсутствие значения не влияет на правило. Параметры не удаляются, редиректа нет, данные для аналитики сохраняются. Canonical остаётся адресом основной страницы. Значение другого параметра, содержащее строку utm_, не вызывает noindex. Обычные URL без UTM остаются индексируемыми.

Локальный scripts/router.php воспроизводит правило для HTML. Это проверяет поведение локального сайта, но не заменяет проверку Apache/nginx на Beget. Если nginx отдаёт HTML в обход Apache, настройку заголовка нужно перенести на уровень nginx/хостинга. Публичный сервер в рамках этой работы не изменялся.

scripts/test-utm.mjs проверяет все страницы sitemap: HTTP 200, наличие noindex только у UTM-вариантов, одинаковое содержимое и canonical, разные позиции и регистр имён параметров, произвольные utm_*, HEAD и отсутствие ложных совпадений. Входит в npm test. Команда npm run test:utm -- https://abs-engineer.ru проверяет фактический публичный сервер. Проверка также включена в деплой до завершения транзакции: отсутствие рабочего заголовка не позволяет объявить деплой успешным.

Clean-param перечисляет стандартные UTM-параметры для Яндекса; произвольные имена utm_* покрывает HTTP-заголовок. Удаление уже известных поисковику дублей произойдёт после их повторного обхода, без обещания конкретных сроков.

Host, robots.txt-noindex и принудительный Crawl-delay не добавлены. Для небольшого статического сайта нет оснований искусственно замедлять обход. Доступ к рабочим страницам разрешён; сам robots.txt не обещает индексацию, рост позиций или заданную частоту посещений робота. robots.txt не заменяет защиту служебных данных на сервере.

## Проверка

scripts/robots-policy.mjs разбирает используемые проектом группы и правила REP с учётом специфичности User-agent и Allow/Disallow. Это локальный проверяющий модуль, а не официальный парсер поисковой системы.

В npm run check добавлено разрешение правил для Googlebot, Googlebot-Image, YandexBot, YandexImages и Bingbot:

- все индексируемые модели и URL sitemap доступны;
- варианты рабочих URL с рекламными метками доступны;
- ресурсы отрисовки и HTML с noindex доступны;
- служебные пути закрыты в каждой применимой группе;
- присутствует ровно по одной секции Googlebot, Yandex и *;
- директива Яндекса не помещена в секцию Googlebot.

Проверка работает с фактическим сгенерированным dist/robots.txt. Текущий sitemap содержит 24 индексируемых URL. После деплоя следует проверить уже публичный ответ robots.txt и повторить проверку в Яндекс Вебмастере и Search Console: текущая работа относится к локальному релизу.
