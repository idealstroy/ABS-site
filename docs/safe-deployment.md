# Деплой АБС по схеме ПТО Онлайн

Используются те же четыре скрипта: deploy-ssh.ps1, deploy-remote.sh, deploy-integrity.ps1 и validate-release.mjs. Изменены только реквизиты АБС, перечни страниц и ресурсов. Локальные _prototype, var и .gitkeep не публикуются.

Подключение: idealstroy_dev@idealstroy.beget.tech, порт 22. Каталог: /home/i/idealstroy/abs-engineer.ru/public_html. Домен: https://abs-engineer.ru. Пароль вводится только в терминале. Имя владельца файлов idealstroy не означает наличие доступной SSH-учётки с этим именем. В показанных ACL public_html, assets и assets/css подтверждены доступ idealstroy_dev и наследуемые права пользователя сайта. Это не проверка всех каталогов сайта и не тест публикации.

## Последовательность

1. Создать на сервере копию текущего сайта в «Backup ABS ГГГГ-ММ-ДД».
2. Собрать рабочую копию сайта, проверить ссылки и сформировать SHA-256 манифест.
3. Передать shell-скрипт и полный архив сборки через обычные ssh.exe/scp.exe во временную папку рядом с public_html.
4. Проверить и распаковать архив. Права 755/644 устанавливаются только внутри временной папки распакованной сборки, не в рабочем сайте.
5. Обновить ресурсы, затем HTML через временные файлы и переименование. Существующие каталоги не переименовывать и не менять их права. При публикации cp --no-preserve=mode не переносит права и ACL из архивной сборки: новые временные файлы получают права при создании в целевом каталоге с его наследуемыми ACL. При откате cp --preserve=mode восстанавливает права и ACL файла из бэкапа без попытки назначить чужого владельца.
6. Проверить опубликованную версию по HTTP. При ошибке восстановить заменённые файлы из копии.
7. После успеха удалить временную папку и старые бэкапы этой схемы, оставив последний. Повторный запуск в тот же день заменяет дневной бэкап.

Это полный деплой, как в ПТО: списка изменённых файлов, Base64, собственного транспорта, проверки чистого Git, блокировки и отдельного механизма ACL больше нет. Точечная адаптация прав для Beget ограничена отсутствием chmod рабочих каталогов и параметрами cp при публикации/откате. Владельцы заменяемых файлов могут измениться на пользователя деплоя; индивидуальные ACL старого файла при публикации заменяются наследуемыми от целевого каталога. Посторонние файлы не удаляются при обычном обновлении. Права существующих каталогов не меняются. Полноценная публикация на Beget с этой адаптацией пока не проверена.

## Команды

```powershell
# Только локальная сборка и проверка, без подключения к серверу
npm run deploy -- -ValidateOnly

# Передать и проверить архив без изменения рабочего сайта и бэкапов
npm run deploy -- -UploadOnly

# Полная публикация: начинает с серверного бэкапа, без подтверждения DEPLOY
npm run deploy
```

Как в ПТО, параметры переопределяются переменными DEPLOY_HOST, DEPLOY_USER, DEPLOY_TARGET_DIR, DEPLOY_PORT, DEPLOY_SITE_URL, DEPLOY_BUILD_DIR и DEPLOY_SSH_KEY. Старые -CheckOnly, -PlanOnly, -Commit, -Yes, -StatusRun и -RecoverRun удалены. Python и дополнительные установки не нужны. Не запускать одновременно несколько деплоев. При потере соединения не повторять запуск до проверки оставшейся временной папки и бэкапа.
