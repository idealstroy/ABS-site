# Техническая основа сайта АБС

## Статус

Документ относится только к пункту 2 дорожной карты. Ни одна коммерческая страница на этом этапе не считается созданной или готовой к индексации.

## Технический аудит

### Что было найдено

- Репозиторий подключен к `https://github.com/idealstroy/ABS-site.git`.
- В корне сохранен рабочий прототип главной страницы и страницы заявки.
- Форма прототипа отправляет письмо через PHP `mail()` на `info@abs-engineer.ru`.
- В проекте есть утвержденные логотипы, полная библиотека Bootstrap Icons и отобранный набор строительных иконок.
- В проекте есть Bootstrap-сетка, дизайн-система, визуальные референсы Example 1-3 и правила страницы.
- Папки `assets` и `outputs` были пустыми и не использовались как источник сборки.

### Что можно переиспользовать

- Подготовленные логотипы и Bootstrap Icons из `Template libraries/иконки`.
- Контакты: `info@abs-engineer.ru` и `+7 917 400-10-59`.
- Фирменные токены из `guide-page1.png` и проектной дизайн-системы.
- Структуру полей ранее созданной формы и утвержденный текст страницы благодарности.
- Корневой прототип как источник для работы над главной страницей в пункте 3.

### Найденные ограничения

- Текущий прототип дублирует header, форму и footer в отдельных HTML-файлах.
- В прототипе используются прямые ссылки на CDN и нет сборочного контроля отсутствующих ассетов.
- Старый обработчик формы не имеет honeypot-поля, временной проверки, ограничения частоты и единой серверной валидации длины полей.
- Реальную доставку письма в почтовый ящик можно подтвердить только после размещения обработчика на Beget. Локальный тест проверяет весь цикл до безопасного файлового транспорта.
- URL политики обработки персональных данных пока не утвержден. В форме оставлен явный комментарий, ссылка не выдумывается.

## Выбранный стек

- HTML5 с семантическими `header`, `nav`, `main`, `section`, `footer`.
- Bootstrap 5.3.3: Grid, Utilities и Components через CDN с SRI.
- Собственный CSS только поверх Bootstrap.
- Open Sans через Google Fonts; другие семейства в исходных стилях запрещены проверкой.
- Нативный JavaScript без библиотек.
- PHP 8+ для серверной отправки формы.
- Node.js только локально для сборки и проверок; на Beget загружается содержимое `dist`.

Beget поддерживает PHP-обработчики и отправку через `mail()`. Перед публикацией необходимо выбрать актуальную версию PHP в панели Beget и проверить доменную почту, SPF/DKIM и фактическую доставку тестового письма.

## Дерево проекта

```text
src/
  assets/           # фирменные CSS и JS
  components/       # единые HTML-компоненты
  data/             # контакты, навигация, модели страниц
  server/           # обработчик и серверная валидация формы
  templates/        # базовый и три коммерческих типа шаблонов
scripts/            # сборка, локальный запуск и проверки
docs/               # техническая документация
dist/               # пересоздаваемый production-вывод
Template libraries/ # утвержденные библиотеки и референсы, не изменяются сборкой
```

## Три типа шаблонов

1. `home` - главная федерального зеркала.
2. `category` - страница категории второго уровня.
3. `specialist` - страница специалиста третьего уровня.

Технические предпросмотры выводятся в `/_prototype/` с `noindex, nofollow`. Они показывают DOM, Bootstrap-сетку и состояния компонентов, но не содержат готового коммерческого текста.

Шаблон главной также содержит отдельный блок карточек специалистов третьего уровня. Он получает названия, иконки и 13 утвержденных URL из одного источника данных `src/data/pages/prototype-home.json`. Пока страницы специалистов не собраны по дорожной карте, их маршруты помечены как `planned`: карточки уже формируют будущую SEO-перелинковку, а проверка не считает их случайными ссылками.

Выпадающие пункты header «Водители» и «Машинисты» используют этот же источник и автоматически дополняются при создании страницы по URL соответствующего раздела. Для меню берется `navigationLabel`, а если он не задан - H1 без начального слова «Подбор». Это исключает ручное дублирование названий в header.

## Общие компоненты

- header и мобильное Bootstrap-меню;
- breadcrumbs;
- карточки;
- CTA;
- FAQ на Bootstrap Accordion;
- открытая форма заявки;
- footer;
- состояния загрузки, ошибки, успешной отправки и фокуса.

Каждый компонент хранится в одном файле в `src/components` и подключается сборщиком ко всем шаблонам.

## Модель страницы

Обязательные поля:

- `output`, `path`, `template`, `pageType`;
- `seo.title`, `seo.description`, `seo.robots`, `seo.canonical`, `seo.openGraph`;
- `h1`, `blocks`, `cta`, `faq`, `breadcrumbs`, `links`, `images`, `schema`;
- `region.city`, `region.city_genitive`, `region.region`, `region.region_slug`, `region.phone`, `region.email`.

Пустые или неподтвержденные значения не подменяются вымышленными данными. Индексируемая страница не пройдет проверку без Title, Description, H1 и canonical.

## SEO-каркас

- поддержка canonical только из данных страницы;
- robots для каждой страницы;
- Open Graph включается только явным параметром;
- JSON-LD выводится только из заполненного поля `schema`;
- breadcrumbs готовы для последующего BreadcrumbList;
- `sitemap.xml` на этапе каркаса пустой;
- `robots.txt` запрещает индексацию всей технической сборки.

## Ассеты

- Логотипы копируются из `Template libraries/иконки` во время сборки.
- Иконки копируются из `Template libraries/иконки/bootstrap-icons-repo/icons` по утвержденному списку.
- Иконки интерфейса декоративные и получают пустой `alt`.
- Контентные изображения в последующих пунктах должны иметь осмысленный `alt`, размеры `width` и `height`, подходящий формат и `loading="lazy"`, кроме изображения первого экрана.
- Неподтвержденные изображения не добавляются.

## Формы и события

- Поля: имя, телефон, почта, кого подобрать, регион/объект, комментарий.
- Скрытые данные: исходная страница, тип страницы, город, региональный slug и время начала заполнения.
- Клиентская проверка построена на Bootstrap validation.
- Сервер повторно проверяет обязательные поля, длины, телефон и email.
- Защита: honeypot, минимальное время заполнения и ограничение запросов в PHP-сессии.
- Production-транспорт - PHP `mail()` на `info@abs-engineer.ru`.
- Локальный транспорт - запись в тестовый файл без отправки писем.
- События: `form_start`, `form_validation_error`, `form_submit`, `form_success`, `form_error`. Они отправляются в `dataLayer`, если аналитика будет подключена позже.

## Служебные маршруты

- `/request/` - открытая форма заявки;
- `/thanks/` - подтверждение отправки;
- `/404.html` - страница для ненайденных адресов;
- `/actions/send-request.php` - обработчик формы;
- `/_prototype/home/`, `/_prototype/category/`, `/_prototype/specialist/` - технические предпросмотры.

Служебные и технические маршруты не входят в коммерческую SEO-структуру.

## Локальная проверка формы

`npm test` запускает PHP-сервер с `ABS_FORM_TRANSPORT=file`, отправляет корректную тестовую заявку, проверяет редирект на `/thanks/`, затем отправляет некорректную заявку и проверяет редирект с ошибкой. Реальное письмо при этом не отправляется.

## Размещение на Beget

1. Выполнить `npm test`.
2. Выполнить `npm run build`.
3. Загрузить содержимое `dist` в каталог сайта на Beget.
4. Убедиться, что выбран PHP 8+ и функция `mail()` доступна.
5. До релиза не снимать запрет индексации в `robots.txt`.
6. На тестовом домене отправить заявку и проверить письмо в `info@abs-engineer.ru`.
7. Настроить SPF/DKIM для доменной почты до публичного запуска.

## Критерии приемки пункта 2

- сборка воспроизводится командой `npm run build`;
- три типа шаблонов используют единый DOM и компоненты;
- используется только Bootstrap 5 и фирменный CSS поверх него;
- пользовательский CSS использует только Open Sans и утвержденные цвета;
- служебные страницы и форма собраны;
- локальный тест формы проходит полный цикл;
- проверки DOM, ссылок, ассетов и базовой доступности проходят;
- технические страницы закрыты от индексации;
- коммерческие страницы еще не считаются готовыми;
- техническая основа показана пользователю и ожидает утверждения.
