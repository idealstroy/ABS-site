## Блокирующие замечания

1. **Новые страницы закрыты от индексации.** /slesari/ и две дочерние страницы слесарей имеют noindex, nofollow. Canonical, Open Graph, Twitter Card и JSON-LD в их HTML отсутствуют; новых страниц нет в sitemap. Причина — status draft, а генератор SEO выводит индексируемую разметку только для ready. Для превью это ожидаемо, для релиза — не готово.

2. **Нет страницы моториста по согласованному URL.** /mashinisty-spetstehniki/motorist-tsementirovochnogo-agregata/ отсутствует в dist. Есть только /_prototype/motorist-tsementirovochnogo-agregata/. Новый специалист также не добавлен в категорию и меню машинистов. robots.txt закрывает /_prototype/.

3. **Ошибка Service в исходных моделях трёх специальностей.** Поле schema у моториста, слесаря ДСТ и слесаря АМ содержит название «Отбор машинистов автовышки и автогидроподъемника» и URL страницы автовышки. Это наследство шаблона. Сейчас ошибочные данные не попадают в HTML из-за draft; простое переключение на ready выведет чужую услугу. Нужно сформировать отдельный Service для каждой специальности с правильными названием, URL и поставщиком. Категория /slesari/ имеет schema: [], поэтому при включении ready автоматический граф сам по себе не добавит ей Service.

4. **Сборщик и проверяющий скрипт по-разному понимают состав страниц.** scripts/build.mjs создаёт два дополнительных URL слесарей из planned-specialties, scripts/check.mjs читает только исходные файлы src/data/pages. Нужно единое разрешение моделей или полноценные исходные модели для согласованных URL. Иначе check и npm test не проходят.

5. **Перелинковка категории ведёт на превью.** Две карточки /slesari/ ссылаются на /_prototype/... вместо согласованных /slesari/slesar-po-remontu-dst/ и /slesari/slesar-po-remontu-am/. В хэдере новые ссылки правильные и их локальные файлы существуют. Перед релизом карточки нужно привести к окончательным адресам.

## Микроразметка

В готовом HTML трёх существующих новых URL нет ни Service, ни WebPage, ни BreadcrumbList, ни FAQPage. У отсутствующего URL моториста HTML нет. Поэтому валидировать новую разметку внешним валидатором пока нечего. На остальных страницах локальная проверка синтаксиса JSON-LD ошибок не обнаружила; это не подтверждает семантическую корректность всех старых графов.

Для выпуска проверить: правильный Service и его provider/areaServed; self-canonical и WebPage; BreadcrumbList с реальными родителями; соответствие FAQ видимому тексту. Названия пунктов FAQ раздела «Слесари» по требованию пользователя являются утверждениями или CTA: их нельзя бездумно переносить в Question.name как вопросы. Нужна осмысленная разметка либо отказ от FAQPage на этой странице. Не менять видимые заголовки ради schema.

Документация: https://schema.org/Service и https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data. Разметка должна описывать фактическое содержимое страницы; ни валидный JSON, ни наличие schema не гарантируют расширенное представление в поиске.

## Что проверено успешно на трёх существующих новых URL

- Title и meta description заполнены; ровно один H1 на страницу.
- У изображений заполнены alt; отсутствующих локальных ресурсов и ссылок на несуществующие файлы не найдено.
- Яндекс-верификация 4af3edb4f96f2c09 присутствует один раз в head; старый ключ 0a783d38e5c12117 отсутствует.
- Инициализация Метрики 112567157 — один раз, noscript watch присутствует.
- Один хэдер и одна встроенная секция заявки на странице; меню слесарей использует согласованные URL.
- robots.txt не закрывает весь сайт, содержит sitemap и закрывает технические preview-адреса.

## Дополнительные замечания

- В форме и футере осталась заглушка ссылки на политику обработки персональных данных. Это общая недоработка сайта, а не новая правка футера; футер в этом аудите не изменялся. Для исправления нужен существующий согласованный URL политики.
- Изображения новых страниц пока относятся к водителям/машинистам и не показывают ремонтную службу. Alt описывает фактические изображения; это не ошибка alt, но тематическое соответствие слабое.
- В страницах слесарей унаследованы шаблонные показатели «3 дня», «35+», «5+ лет», «24/7». В рабочих текстах новых специальностей подтверждения этих обещаний нет; требуется подтверждение компании или удаление этих показателей перед публикацией.
- Полный сценарий формы в npm test не выполнялся из-за ошибки check. Доставка писем и внешние интеграции этим аудитом не подтверждены.
- Проверка после активации в deploy-ssh.ps1 пока перечисляет старые адреса, а не четыре новых. Валидатор release не должен считаться единственным критерием SEO-готовности.
- Локальная копия на согласованных URL слесарей и старые превью имеют одинаковый контент, что допустимо только при корректной обработке технических дублей. Превью должны оставаться техническими; ссылки production-страниц не должны вести на них.

## Порядок подготовки релиза

Сначала исправить модели и Service, создать моториста по согласованному пути, привести карточки к окончательным URL. Затем настроить для согласованных страниц canonical, индексируемый статус, OG и sitemap; проверить BreadcrumbList и решение по FAQPage. Устранить расхождение build/check, повторить npm test и валидацию релиза. До этого текущую сборку не считать готовой к публикации новых страниц.

Подробные машинные результаты: audit.json. Живой сайт, DNS, индексация в Вебмастере и результаты внешних валидаторов не проверялись. Деплой не запускался.
